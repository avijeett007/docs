## Why tool modes exist

A voice-agent token with `scope:'all'` previously gave the LLM access to ~283 tools simultaneously (155 from ElevenLabs alone). This degraded tool-selection accuracy and added latency.

**Meta mode** solves this by giving the agent two gateway tools instead:

- `internal_search_tools` — keyword-ranked search across all available tools (returns name + description)
- `internal_execute_tool` — generic executor: the agent passes a tool name + arguments and the platform dispatches it

The agent now navigates a catalogue rather than holding 283 simultaneous function definitions.

## Token types and their defaults

| Token minted by | Default mode | Can change? |
|---|---|---|
| Voice agent (auto-minted at call start) | `meta` (~11 tools) | Platform default (managed by Knotie) |
| Partner API key / manual token | `full` (~283 tools) | Via `toolMode` JWT claim |

Voice agents default to `meta` to protect LLM context and tool accuracy. Partner-minted tokens (Cursor, Claude Desktop, Windsurf, automation scripts) still receive full tool access by default.

## JWT claims for fine-grained control

When minting a token manually you can include two optional claims:

### `toolMode`

```json
{
  "toolMode": "meta"
}
```

Values: `"full"` | `"meta"`. Omitting the claim defaults to `"full"` for partner-minted tokens.

### `apps` (limit the token to chosen apps)

```json
{
  "apps": ["gmail", "hubspot"]
}
```

When present, the token can only use tools from the listed apps. Calls to any other app are refused. The older name `allowedApps` still works the same way; if you send both, `apps` wins. Leave both out to allow every app the token's scope includes.

### Mailbox access level

A token with access to all apps also includes the customer's connected mailbox, if they have one. You can set how much it may do with the `mailboxAccessLevel` option:

| Value | What the token can do |
|---|---|
| `read` (default) | Read emails and threads. |
| `organise` | Read, plus label, archive, and move emails. |
| `draft` | The above, plus write drafts. |
| `send_approval` | The above, plus submit drafts for the customer to approve before sending. |
| `send` | The above, plus send emails directly. |

To keep a token away from email entirely, use `apps` and leave the mailbox out of the list.

## Setting these options in the portal

The **Create Token** tab in the Partner Portal covers the most common case. Its **Tool Scope** menu offers **All apps and tools**, **Specific apps** (the same as `apps`), and **Specific tools**.

## How agents use meta mode

In meta mode the agent workflow changes:

1. **Discover** — call `internal_search_tools` with a keyword (e.g., `"social post"`) to get relevant tool names and descriptions.
2. **Execute** — call `internal_execute_tool` with the tool name and parameters.
3. Rate limits, credit charges, scope, and app-limit enforcement all apply inside `internal_execute_tool` exactly as they do for direct tool calls.

## Revert to full mode for voice agents

Voice-agent tool mode is a platform-level default managed by Knotie. If you need your voice agents to receive the full tool list (e.g., for debugging a tool-selection issue), contact Knotie support to have the default changed for your account. The change applies to newly minted voice-agent tokens; in-flight tokens are unaffected until the call ends.

## New agent-facing tools

The following tools are now available to agent tokens with appropriate scope:

| Tool | What it does |
|---|---|
| `MEDIA_LIST_ASSETS` | List a customer's uploaded media assets |
| `MEDIA_IMPORT_FROM_URL` | Download an external URL into the customer's media library |
| `SOCIAL_POST_PUBLISH` | Immediately publish a post to specified social platforms |
| `SOCIAL_POST_SCHEDULE` | Schedule a post for a future date/time |
| `SOCIAL_POST_LIST` | List upcoming scheduled social posts |

`MEDIA_IMPORT_FROM_URL` runs the URL through a safe-fetch validator (HTTPS-only, private/loopback IP rejection, ≤3 redirects) before downloading.

## Partner-page WebMCP tools

Partner tokens (Cursor, Claude Desktop, and similar) can call tools that operate directly on Partner Portal pages. These are registered per-page and give agents the ability to read usage data, check settings, and inspect portal state.

### `get_agent_usage`

Returns call and cost metrics for a named agent. This tool now returns the same five fields the partner portal analytics page uses (`totalCalls`, `totalMinutes`, `totalCost`, `avgCallDuration`, `successRate`). Earlier builds returned zero for every metric due to a parsing mismatch.

**If you have automation that calls `get_agent_usage` and was receiving zero values, re-run it — the tool now returns accurate data.**

### `list_top_agents` — removed

This tool was removed. It claimed to rank agents by call volume, but every agent scored zero because the underlying API endpoints do not return usage fields. A confident wrong result is worse than no result. Use `get_agent_usage` to check usage for a specific agent by name.

### MFA gate and tool registration

When a partner session requires a multi-factor authentication prompt (for example, on a sensitive action), all registered partner-page tools are automatically unregistered until the prompt is dismissed. This prevents agent calls from succeeding through an MFA-gated session. Tools re-register automatically once the prompt closes.

> 📷 **Screenshot needed:** _Add a screenshot or diagram showing the partner session MFA prompt alongside a note indicating tool calls are suspended._

### AI Gateway resale status

The `get_ai_gateway_resale_settings` tool now correctly reports whether AI Gateway resale is **enabled or disabled** for your account. Earlier builds always reported disabled, regardless of actual configuration.

## Kill switch

Partners and platform operators can disable all WebMCP tool registration by setting the `WEBMCP_ENABLED` environment variable. Accepted values (case-insensitive, whitespace-trimmed):

| Disable | Meaning |
|---|---|
| `false`, `0`, `off`, `no`, `disabled` | WebMCP tools will not register — the feature is off. |
| unset or empty | No opinion — WebMCP is on by default. |

<Warning>
Earlier builds only accepted the exact string `false`. Any other value (including `0` and `off`) left the feature on. Operators who tried to disable WebMCP using `0` or `off` should verify the feature is now correctly off after updating.
</Warning>
