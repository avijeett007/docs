## Overview

Knova is a **hosted** AI agent platform — infrastructure is managed by Knotie, not self-hosted by you. It offers advanced capabilities including knowledge bases, a browser-based voice test, and configurable profit margins per customer.

![Knova AI (Hosted) Agents page with Build with AI CTA](/images/screenshots/knova-agents-2026-06-09.png)

## Where to find it

1. In the Partner Portal sidebar, go to **AI Agents → Voice Agents → Knova Agents**.

You'll land on `/partner/ai-agents/knova`.

</Info>

</Note>

## Key features

### Try Agent (Web-Test)

Test your Knova agent directly from the browser before going live:

1. Open the agent's three-dot menu
2. Click **Try Agent (BETA)**
3. Speak with the agent via LiveKit-powered voice session

![Try Knotie web-test modal showing connected agent](/images/screenshots/knova-web-test-modal.png)

The modal shows a live status (`Agent Listening` / `Agent Thinking`) and Mute / End test controls. Test sessions consume your platform credits while connected.

### Customer assignment

Map an agent to a customer to enable:

- Billing and usage tracking
- Profit multiplier configuration
- Analytics configuration

To assign:
1. Open the agent's three-dot menu
2. Click **Assign Customer**
3. Select the customer and set the profit multiplier

![Assign Customer to Agent modal with profit multiplier field](/images/screenshots/knova-assign-customer-modal.png)

### Profit multiplier

The profit multiplier determines how much you bill the customer for AI usage above cost. Default is **1.2x**.

For example:
- Actual AI cost: $0.10/minute
- Profit multiplier: 1.2x
- Billed to customer: $0.12/minute

### Configure metrics

Once an agent is assigned to a customer, you can configure analytics:

1. Open the agent's three-dot menu
2. Click **Configure Metrics**
3. Set up analytics tracking for the agent

</Warning>

- **Try Agent (BETA)** — test in browser

## Connected App Tools

When a Knova agent is **assigned to a customer**, Knotie AI Pro automatically wires in a **live MCP (Model Context Protocol) server** for that customer's connected apps. The Knova LiveKit runtime reads the `advancedConfig.mcpServers` field and registers the server at agent start — so tools from Gmail, Slack, HubSpot, Google Calendar, and any other apps the customer connects are available to the agent **immediately**, without a rebuild.

### How it works

1. On agent create or update, a `scope: all` MCP token is minted for the assigned customer.
2. The token is injected into `advancedConfig.mcpServers` using `streamable_http` transport:
   ```json
   {
     "mcpServers": [
       {
         "name": "knotie_partner_tools",
         "url": "https://<your-connect-hub>/api/mcp",
         "transport": "streamable_http",
         "auth": { "type": "bearer", "token": "<per-customer-token>" },
         "timeoutMs": 120000
       }
     ]
   }
   ```
3. The LiveKit runtime registers this server and exposes connected-app tools to the agent.

> 📷 **Screenshot needed:** _Add a screenshot of a Knova agent's Advanced Config view (or the agent detail) showing the mcpServers entry._

### Customer assignment and token lifecycle

| Event | What happens |
|---|---|
| Agent created with a customer | MCP token minted, injected into `advancedConfig` |
| Agent updated (tools, config, or customer) | New token minted, prior token deactivated, config updated |
| Customer unassigned | Orphaned MCP server entry is stripped from `advancedConfig` |
| Customer reassigned to another tenant | Token re-minted scoped to the new customer |

### Prerequisites

- **Connect Hub** must be configured (`CONNECT_HUB_URL` environment variable). Knova MCP wiring is silently skipped when Connect Hub is unavailable — agent creation never fails because of this.
- **Customer assigned** — agents without a customer do not get MCP wiring.

> 🎬 **Video walkthrough:** _Record a clip showing: (1) a customer connecting a new app, (2) placing a test call via Try Agent (BETA), and (3) the agent using that app's tools automatically._

### Which tools go via MCP vs. static webhooks

Connected-app tools (those with a standard app-slug `appName` like `gmail`, `slack`, `googlecalendar`) are served dynamically through the MCP server. The following tool types still use per-tool webhooks:

- **Custom API integrations** (UUID `appName`) — bespoke wiring not covered by MCP
- **Tools with pre-filled parameter values** — prefills are baked into the webhook description and would be lost via MCP

For the full cross-provider reference, see [Connected App Tools](/agents/connected-app-tools).
