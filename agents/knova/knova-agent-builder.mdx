## What is the Knova AI Agent Builder?

The Knova AI Agent Builder is a conversational interface that lets partners and customers create a configured Knova voice or chat agent through natural language — no manual form-filling required. You describe the business, paste a website URL, or explain the use case, and the builder proposes an agent with a system prompt, voice, tools, and configuration already filled in.

Use the builder when you want to:

- Spin up an agent quickly from a business description
- Draft a system prompt from a live website (paste a URL)
- Configure multi-agent routing (triage + specialists)
- Iterate on a draft in plain English instead of editing fields

## Opening the builder

1. In the Partner Portal, navigate to **Customers** and open a customer record.
2. Click **Manage Agents** (or the AI Agents section in the customer view).
3. Click **+ Add Agent**.
4. On the mode picker, choose **AI Mode** to open the Agent Builder chat panel.
   - Choose **Manual Mode** if you prefer to fill in all fields yourself.

The builder opens as a full-screen chat panel inside the agent modal. The text input is focused automatically — start typing right away.

## Building an agent

### Basic flow

1. **Describe the business or use case.** For example:
   > *An inbound receptionist that books cleanings on Calendly and texts confirmations.*

2. **Paste a URL if you have one.** When the builder detects a URL in your message it will read the page automatically and use it to populate the agent.
   > *Or paste your business URL and I'll read it.*

3. **Review the draft.** The builder streams its reasoning, then presents a proposed agent configuration.

4. **Refine or accept.** Ask for changes in plain English, or click **Accept** to save the agent.

> 🎬 **Video walkthrough:** _Record a short clip walking through creating an agent end-to-end — from opening the AI Mode panel, typing a business description, and accepting the proposed agent configuration._

### What's in the proposal

The builder produces a complete agent configuration with:

- Agent name and type (`inbound` / `outbound` / `web` / `multi_agent`)
- Communication channel (`telephony` or `web`)
- Agent mode (`essential` / `moderate` / `premium`)
- System prompt and greeting message
- Function calls (tool integrations)
- Multi-agent personas and routing (if applicable)

Review the proposal in the chat. Give feedback if you want changes — the builder will revise and re-propose. When you are satisfied, click **Apply to form**. The proposal is loaded into the standard agent creation form, where you can make final tweaks before saving.

## Autonomous web access — no toggle required

The builder can read web pages and run searches on its own, without any partner-facing toggle. (Earlier "Web search" / "Keep Web search on" toggles were removed in knotie-ai-pro#848.)

| Situation | What the builder does |
|---|---|
| You paste a URL in your message | Calls `fetch_url` and reads the page content before proposing the agent |
| You name a website ("their site is ipswich.plumbing") | Calls `fetch_url` with the URL it infers |
| The business profile has a `businessWebsite` field | Calls `fetch_url` to pull current hours, services, pricing detail |
| No URL is in scope and the builder needs to find one | Calls `search_web` with a relevant query |

### URL detection indicator

When the builder detects a URL in your input field, a teal badge appears above the text area:

> **URL detected — the builder will read it**

This is informational only — no action is required. The builder will fetch the page as part of its reasoning.

> 📷 **Screenshot needed:** _Add a screenshot of the teal "URL detected — the builder will read it" badge in the Agent Builder input area._

### What happens when a fetch fails?

If a site blocks the crawler, returns a 4xx error, or times out, the builder:
- Acknowledges the failure briefly in its response
- Asks you to paste the relevant text in plain English
- Continues building the best draft it can without blocking

You do not need to retry or toggle anything.

While the builder is working, phase labels appear above the chat to show what it is doing:

| Phase label | What it means |
|---|---|
| *Reading your request* | Parsing your message |

| *Searching the web* | Running a web search to find a URL |
| *Reading your business profile* | Loading business context from the customer record |
| *Understanding the app integrations* | Inspecting available tool integrations |
| *Drafting the agent* | Composing the system prompt and configuration |

## Multi-agent configurations

The builder supports creating multi-agent setups where a routing agent hands off to specialised persona agents (e.g. sales, support, billing).

### Routing modes

| Mode | Description |
|---|---|
| `triage_specialist` | A triage persona routes to one of several specialists based on the caller's intent |
| `linear` | Personas hand off in a fixed sequence |
| `freeform` | Each persona decides whether to hand off |

### Requirements for multi-agent proposals

- At least **2 personas** defined
- A **routing** block with a valid mode
- An **entryPersonaId** pointing to the first persona
- All persona IDs referenced in routing must exist in the `personas` list

When editing an existing multi-agent setup:
- All personas are loaded correctly into the builder context
- The `entryPersonaId` (routing agent) is preserved
- The builder can update individual personas or the routing logic

## AI Analytics gate

Knova agents support **AI Analytics** (call metrics and insights). The Partner Portal reflects your account's AI Analytics status:

- **Enabled**: you can configure and save metrics for any Knova agent.
- **Disabled**: the Configure Metrics modal shows a warning banner and the **Add / Save** buttons are disabled, so you know the settings won't take effect until AI Analytics is turned on at the partner level.

## Saving behaviour

- While the agent is being saved (the save operation is in flight), closing the modal does **not** trigger an "unsaved changes" confirmation. The save will complete normally.
- If you attempt to close the modal before saving, a confirmation dialog asks whether you want to discard your changes.
- Once the save completes, the modal closes automatically.

## Phone number assignment after building

After the builder creates an agent, you can assign a phone number to it from the **Assign Phone Number** step inside the agent modal.

## Voice selection notes (Inworld)

When the builder proposes an Inworld voice, gender is detected correctly from the voice catalogue. Previously, voices with descriptions containing the word "female" could be incorrectly matched as "male" due to a substring overlap. This is fixed — Ashley, Craig, and other Inworld voices now resolve to the correct gender.

## Builder reliability

The builder API allows up to **120 seconds** per turn (increased from 60 s in knotie-ai-pro#832) to accommodate complex multi-agent configurations.

- Simple single-agent builds typically complete in under 30 seconds.
- Complex multi-agent builds with 4–6 tool calls may take 60–90 seconds.
- If the builder appears stuck for more than 2 minutes, close the modal and try again.

### Proposal validation rules

Every proposal is validated before being presented:

| Rule | Detail |
|---|---|
| System prompt length | Max 15,000 characters per persona |
| Multi-agent: persona count | Minimum 2 personas |
| Multi-agent: routing | Must include a valid routing block and `entryPersonaId` |
| Persona references | All IDs in routing must match a defined persona |

If a proposal violates a rule, the builder self-corrects on the next turn rather than surfacing an error to you.

## Configuration reference (self-hosted)

Partners running their own Knotie AI Pro instance configure the builder LLM via `.env`:

| Variable | Purpose | Recommended value |
|---|---|---|
| `KNOVA_BUILDER_BASE_URL` | LLM provider endpoint | e.g. `https://api.openai.com/v1` |
| `KNOVA_BUILDER_API_KEY` | API key for the provider | Your OpenAI / provider key |
| `KNOVA_BUILDER_MODEL` | Model used for the builder | `openai/gpt-4.1-mini` |
| `KNOVA_BUILDER_AUTH_SCHEME` | `Bearer` (default) or `Basic` (Inworld) | `Bearer` |
| `KNOVA_BUILDER_TEMPERATURE` | Sampling temperature | `0.7` |

### Recommended models

The builder requires a model with **reliable tool-calling**. Reasoning-heavy models can produce long chains-of-thought without ever calling `propose_agent_config`.

**Confirmed working:**

| Provider | Model ID |
|---|---|
| OpenAI (direct) | `openai/gpt-4.1-mini` |
| OpenAI (via Inworld) | `openai/gpt-4o-mini` |
| Anthropic (via Inworld) | `anthropic/claude-haiku-4-5` |

<Warning>
Avoid `inworld/ab-test-models` as the builder model. That family uses a reasoning-heavy architecture with weak tool-call support, which causes the builder to fail on multi-step tool loops.
</Warning>

<Tip>
For Inworld-hosted deployments, use `openai/gpt-4.1-mini`. It has reliable tool use and is cost-efficient for agent builder sessions.
</Tip>

## Troubleshooting

**Builder chat shows a spinner for a long time**
The builder LLM is working through a multi-tool turn. Wait up to 2 minutes before closing.

**Builder times out before finishing**
The builder route allows up to 120 seconds per turn for reasoning-heavy models. If you see timeout errors:
- Switch to a faster model (`gpt-4.1-mini`, `claude-haiku-4-5`)
- Split the request into smaller steps (one persona at a time for multi-agent configs)

**Input field has no cursor when the modal opens**
Fixed in knotie-ai-pro#848. The input now auto-focuses correctly even when the builder is opened from inside another modal. If you still see this, ensure your browser is up to date.

**Fetch fails on every URL I paste**
- Check that `SERPER_API_KEY` (or equivalent web-search config) is set in your `.env` file (self-hosted only)
- Some sites block server-side crawlers by design. Paste the relevant text from the page directly into the chat and the builder will use it

**"No personas yet" when editing an existing multi-agent**
This was fixed in knotie-ai-pro#832. If upgrading from an older version, re-open the agent in the builder to reload the persona list.

**Applied proposal but form fields are empty**
Click **Apply to form** in the builder chat — the proposal does not populate the form automatically.

**Builder thinks but never produces a proposal**
The configured `KNOVA_BUILDER_MODEL` is likely a reasoning-heavy model that doesn't call tools reliably. Switch to `openai/gpt-4.1-mini` or `anthropic/claude-haiku-4-5`.
