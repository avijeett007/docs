## What changed

### Rejection holds

Previously, when a client rejected an hours approval, the hold on those hours was
released immediately. This caused an edge case where a partner could change the estimate
and re-propose, but the previously held hours were already freed.

**After this fix:** rejection correctly holds the hours in a pending state until the
partner explicitly cancels or proposes a revised estimate, so the balance accurately
reflects in-flight negotiations.

### Mobile layout

The project list page and task drawer were difficult to use on small screens.

**After this fix:** both the partner's project list and the portal task list use a
responsive layout that stacks correctly on mobile. The task drawer opens as a bottom
sheet on small screens rather than as a side panel.

> 📷 **Screenshot needed:** _Add a screenshot of the portal task list on a mobile screen
> (375 px) showing the stacked layout and the bottom-sheet task drawer._

### Light and dark theme readability

Several text colours in the project pages were taken from the wrong theme token, making
labels and status chips unreadable in dark mode (or in light mode if the wrong token was
used).

**After this fix:** all project management components use the correct semantic theme
tokens (`text-foreground`, `text-muted-foreground`, `bg-card`, etc.), so the UI reads
correctly in both light and dark mode.

> mode and dark mode showing legible status chips and labels in both themes._
