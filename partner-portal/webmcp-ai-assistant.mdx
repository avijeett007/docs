## What it is

**WebMCP** is an in-browser capability that lets a compatible AI agent (such as Claude, running in a Chrome or Edge tab) see what the current Partner Portal page can do and act on your behalf.

Instead of clicking through menus and forms yourself, you can ask your agent:

- "What pages can I use in this portal?"
- "Go to white-label settings and list what isn't configured."
- "What is my current credit balance and burn rate?"
- "Search for a customer named Acme Corp."
- "Open the phone number purchase dialog for a US number starting with 415."

The agent uses **named tools** — one per action a page already exposes — to answer and act. It never calls anything the page doesn't already call, and consequential actions (spending money, sending campaigns, deleting data) always require your confirmation in the browser.

## How to enable it

WebMCP requires two things:

1. **The `NEXT_PUBLIC_WEBMCP_ENABLED` environment variable set to `true`** on your deployment. Ask your platform administrator, or set it in your `.env` file if you are self-hosted.

2. **A browser that supports the WebMCP origin-trial.** Chrome and Edge with the `document.modelContext` origin-trial token work today. In local development you can bypass this via `chrome://flags/#enable-webmcp-testing`. For production, register an origin-trial token and add it to `NEXT_PUBLIC_WEBMCP_ORIGIN_TRIAL_TOKENS`.

Once enabled, the partner shell mounts the WebMCP provider automatically on every page. No per-page setup is needed.

## Core tools — always available

These tools are mounted on every page in the partner layout:

| Tool | What it does |
|---|---|
| `whoami` | Your partner ID, business name, email, role, plan, and active permissions. |
| `list_areas` | Every portal area with a one-line description and whether your plan includes it. The most useful tool for an agent that just opened the portal. |
| `go_to` | Navigate to any named area (e.g. `go_to('phone-numbers')`). |
| `get_page_context` | Current route, area name, and what tools are available here. |
| `get_account_summary` | Live credit balances, customer count, active agent count, active phone numbers, and items needing attention. |
| `search` | Query across customers, agents, and numbers in one call. |
| `go_to_dashboard` | Return to the Dashboard from any page. |
| `get_my_level` | Current partner level, streak, and the active challenge — stays available as you navigate through setup steps. |

## Security model

WebMCP is designed so that adding a tool never gives an agent a capability the signed-in person does not already have.

| Property | How it is held |
|---|---|
| **No new API routes** | Every tool calls an endpoint the page already calls. Nothing new is exposed to the internet. |
| **Session-based auth** | Tools use the existing session in the browser tab — no token is minted or stored. |
| **Server-side enforcement** | RBAC, tenant scoping, and plan gating apply on every call, exactly as for a click. |
| **Consequential actions require confirmation** | Any tool that spends money, deletes data, or sends communication is a `start_*` tool that opens the existing confirmation dialog. The agent cannot confirm. |
| **No secret egress** | Tool results are scrubbed before reaching the agent. Credential material is never fetched in the first place. |
| **Annotations are enforced** | A mutating tool cannot be shipped with `readOnlyHint`. The `defineTool` factory derives annotations from the tool's declared `kind`. |
