## Overview

VPS (Virtual Private Server) management lets partners purchase, provision, and manage cloud VPS instances from **Contabo**, then assign them to their customers. It's a self-serve infrastructure layer within the Partner Portal.

![Knotie AI Pro Partner Portal VPS management page](/images/screenshots/vps-page-2026-06-09.png)

## Where to find it

1. Partner Portal → **VPS Servers** in the sidebar (under **INFRASTRUCTURE**)

## Purchase a VPS

1. Click **Buy VPS**
2. Select a **plan** (Cloud VPS 10–60)
3. Select a **region** (EU, US — more coming soon)
4. Optionally assign to a **customer**
5. Optionally set a **display name**
6. Click **Proceed to Payment**

## Instance states

VPS instances move through these states:

| State | Description |
|-------|-------------|
| `pending_payment` | Order placed, awaiting payment |
| `pending_provisioning` | Payment received, being set up |
| `active` | Live and operational |
| `suspended` | Paused due to non-payment or issues |
| `cancelled` | Terminated |

> ℹ️ Each provisioned VPS appears as an **instance card** carrying a colored status badge that matches the table above — e.g. amber `pending_provisioning`, green `active`, grey `suspended`. The cards render only once at least one VPS exists on the account; on a fresh account this area reads "No VPS instances yet. Purchase one from the Purchase tab." Capture from an account with a live instance.

## Assign to customer

Each instance can be assigned to a customer:

1. Open the **Assign to Customer** dropdown on the instance card
2. Select the customer (or "Not assigned")
3. Confirm

Unassigned instances show "Not assigned to a customer."

## View instance details

Click on an instance card to see:
- Plan specs
- Region
- Partner price
- Creation date
- Status badge

> ℹ️ Clicking an instance card opens a **details panel** listing the plan specs, region, partner price, creation date, and the current status badge in a single read-only view. It renders only for an existing instance, so capture it from an account that has a provisioned VPS.

## Credentials

For `active` instances, you can request root credentials:

1. Click **Request Credentials**
2. Credentials are sent to your email and displayed on screen
3. Password is shown in a monospace box

> ℹ️ After you click **Request Credentials** on an `active` instance, a **reveal panel** displays the root username and password, with the password shown in a monospace box (and also emailed to you). The panel appears only for a live active instance, so capture it the first time you request credentials on a real VPS.

### Regenerate SSH keys

To regenerate SSH keys for an instance:

1. Click **Regenerate SSH Keys**
2. Confirms the action
3. New keys are generated

### Fix credentials

If credentials aren't working, use the **Fix Credentials** modal:

- **Auto-fix**: Platform automatically generates fresh credentials and injects them via SSH
- **Manual**: Enter your current root password, and the platform SSHs in to install a new key

> ℹ️ The **Fix Credentials** modal offers two tabs: **Auto-fix** (the platform generates fresh credentials and injects them over SSH for you) and **Manual** (you enter your current root password so the platform can SSH in and install a new key). The modal is reachable only from an active instance, so capture it from an account that has one.

## Reinstall with App

You can reinstall the OS with one-click apps:

### Single App mode

Select one app to install. Options include:
- Clean Ubuntu OS
- Docker + Portainer
- Domain controllers
- Other curated apps

### Package Builder mode

Select multiple apps to install together as a package:

- **Port conflict detection**: If two apps use the same port, a warning blocks installation
- **RAM estimation**: Shows total RAM required across selected apps
- **Badge indicators**: "Verified" (passed testing), "Under construction" (being fixed), "New", "Popular"
