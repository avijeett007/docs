## What the App Catalog is

The VPS App Catalog is the app picker inside the Partner Portal's **VPS** section. It lets you choose which software stack to install when you provision or reinstall a VPS instance for a customer.

Each card in the catalog represents a deployable application bundle (e.g., OpenClaw, n8n, Nextcloud). You can install a single app or compose a multi-app **Package** in one click.

### App badges

Each card can display one or more badges:

| Badge | Meaning |
|---|---|
| **✨ New** | The upstream project is less than ~1 year old, or it is a Knotie-native bundle released recently |
| **🔥 Popular** | Widely-deployed in the self-hosted ecosystem (broadly: 100K+ GitHub stars or de-facto brand) |
| **✅ Verified** | This bundle has been tested end-to-end against the automated VPS matrix runner |
| **⚒ Under construction** | The app's deploy script has a known issue and is being fixed — install is temporarily disabled |
| **Platform default** | This bundle (Docker + Portainer) is the default stack Knotie provisions for new VPS instances |
| **Added** | (Package mode only) This app is already in your package |

## Install modes

### Single app install

1. Click any app card to select it. The selected card gets a purple highlight.
2. Click **Select for Install** in the detail panel, or select directly from the grid.
3. Confirm the reinstall in the confirmation dialog.

**Clean Ubuntu** is always available as the first card in single-app mode — choose it to provision a plain server with no pre-installed software.

### Package install (multi-app)

1. Switch to **Package** mode using the toggle at the top of the picker.
2. Click any app card to add it to your package. Added cards show an **Added** badge.
3. Click a second time to remove an app from the package.
4. Build the combination you want, then confirm.

The platform validates port conflicts between selected apps before allowing the install. If two apps in your package share a port, a warning is shown listing the conflicting apps.

## App availability states

Every app in the catalog has one of three availability states. The state controls what you can do with it.

| State | Indicator | Can install? | Shows in package settings? |
|---|---|---|---|
| **available** | No badge | Yes | Yes |
| **verified** | Green ✅ Verified badge | Yes | Yes, with a green checkmark |
| **under_construction** | Amber ⚒ badge, dimmed card | **No** | Yes, but disabled (greyed out, cursor `not-allowed`) |

When you try to install an app that is `under_construction`:
- The **Select for Install** / **Add to Package** buttons are replaced with an amber notice: _"This app is under construction — install is disabled while it's being fixed."_
- The main **Reinstall** button is disabled as long as any selected or packaged app is under construction.
- The catalog deploy API returns HTTP `422` with the message: `{app name} is under construction and cannot be installed yet`.

This state is managed by the Knotie team and clears automatically when the bundle is fixed and re-verified.

## VPS App Catalog API (Partner & White-label)

### List available applications

```
GET /api/partner/vps/applications
GET /api/whitelabel/vps/instances/{instanceId}/applications  (white-label variant)
```

Requires partner authentication. Returns an array of application objects.

**Response shape (per application):**

```json
{
  "applicationId": "openclaw",
  "name": "OpenClaw",
  "description": "Production AI agent runtime with Knotie Gateway integration",
  "emoji": "🦀",
  "category": "ai",
  "displayCategory": "ai-agents",
  "isNew": true,
  "isPopular": false,
  "isPaid": false,
  "setupFeeCents": 0,
  "website": "https://openclaw.dev",
  "githubUrl": "https://github.com/...",
  "license": "MIT",
  "logoUrl": null,
  "features": ["llm", "memory", "tools"],
  "tags": ["ai", "agent"],
  "accessPort": 18789,
  "ramMb": 2048,
  "availability": "verified",
  "catalogAvailability": "available"
}
```

**New fields added in this release:**

| Field | Type | Description |
|---|---|---|
| `displayCategory` | `string` | Fine-grained UI bucket used for section grouping (e.g. `"ai-agents"`, `"automation"`, `"media"`) |
| `isNew` | `boolean` | `true` if the upstream project is less than ~1 year old |
| `isPopular` | `boolean` | `true` if the upstream project is widely deployed |
| `availability` | `"available" \| "verified" \| "under_construction"` | Controls whether the app can be installed via the **Reinstall** (cloud-init) flow |
| `catalogAvailability` | `"available" \| "under_construction"` | Controls whether the app can be installed via the **Catalog Deploy** flow |

> **Note:** `availability` and `catalogAvailability` are independent. An app can have a working catalog-deploy script even if its cloud-init runcmd is broken (or vice versa).

### Catalog deploy

```
POST /api/partner/vps/instances/{instanceId}/catalog/deploy
POST /api/whitelabel/vps/instances/{instanceId}/catalog/deploy  (white-label variant)
```

If the target app's `catalogAvailability` is `"under_construction"`, the endpoint returns:

```json
HTTP 422
{ "error": "{App name} is under construction and cannot be installed yet" }
```

### Reinstall (cloud-init)

```
POST /api/partner/vps/instances/{instanceId}/reinstall
```

If any app in the requested install set has `availability === "under_construction"`, the endpoint returns:

```json
HTTP 422
{ "error": "Package contains apps under construction: {App A}, {App B}" }
```

## Package management (Settings page)

In the partner portal **VPS Settings**, when you create or edit an app package, under-construction apps appear in the selector with:
- An amber ⚒ icon and dimmed styling
- The `disabled` attribute set — clicks are ignored
- A tooltip: _"Under construction — cannot be added to a package yet"_

Verified apps (in the available/verified state) show a green checkmark in their unselected state so you can identify the most stable choices at a glance.
