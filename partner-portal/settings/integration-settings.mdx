<Warning>
The **Settings → Integration Settings** page described in earlier versions of this doc **no longer exists in the live Partner Portal.** The Settings sidebar was redesigned in 2026; it now has 5 sub-items (Profile Settings / Partner API Keys / Email Domain Management / Plans & Billing / White-Label Portal) — "Integration Settings" is not one of them. Provider keys now live in **Settings → Partner API Keys → Platform API tab**.
</Warning>

## What "Integration Settings" used to be

In an older release of the Partner Portal, provider credentials (GHL / VAPI / Retell / Ultravox) were configured in a dedicated **Settings → Integration Settings** page that surfaced a unified form with these fields:

- **GoHighLevel Calendar ID**
- **GoHighLevel API Key**
- **VAPI API Key**
- **Retell API Key**
- **Ultravox API Key**

That single page no longer exists. Each provider's API key is now managed from a different surface.

## Where provider keys live today

| Provider | Where to add the key today |
|---|---|
| **Platform API key** (Pakt `pkt_…`) | Settings → **Partner API Keys** → **Platform API** tab — generates a generic Knotie API key, not provider-scoped |
| **AI Gateway key** (`sk-knot-…`) | Settings → **Partner API Keys** → **AI Gateway Beta** tab — OpenAI-compatible virtual key for LiteLLM-routed models |
| **MCP token** (`mt_…`) | AI Agents → **MCP Tokens** (top-level sidebar entry) — for MCP-gateway integrations |
| **VAPI / Retell / Ultravox / ElevenLabs / GHL** provider keys | Entered per-import inside each provider's **Import** modal (VAPI Agents, Retell Agents, Ultravox Agents, ElevenLabs Agents, GHL Agents). The portal validates the key against the provider's API on submit. |

### Validation endpoints (used by the live UI)

These were already documented and still apply:

- **VAPI**: validates by calling `https://api.vapi.ai/assistant`
- **Retell**: validates by calling `https://api.retellai.com/list-agents`
- **Ultravox**: validates by calling `https://api.ultravox.ai/api/agents` using `X-API-Key`

If validation fails, you'll see an "invalid API key" message inside the import modal.

## Best practices

- Keep keys in a password manager.
- Rotate keys if a contractor leaves.
- Use separate provider accounts for production vs testing where possible.
- Per-provider keys (VAPI/Retell/Ultravox/ElevenLabs/GHL) are scoped to that provider only — they cannot be used to call another provider's API.
