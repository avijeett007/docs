## What this feature does

By default, the Knotie AI Pro integration gateway MCP server is reachable at `mcp.knotie-ai.pro`. With a **custom MCP domain**, partners on paid tiers can resell the MCP server under their own branded hostname — for example, `mcp.yourcompany.com`.

Clients and AI coding assistants that connect to your MCP endpoint use your domain name, not Knotie's. SSL is handled automatically via Cloudflare — you add a CNAME record and Knotie handles the rest.

## Prerequisites

- An active paid-tier subscription with MCP access
- A domain you control with permission to add DNS records (CNAME)
- The **Custom MCP Domain** option visible in your portal — if it doesn't appear, contact Knotie support to enable the `MCP_WHITELABEL_ENABLED` flag for your account

## How routing works

Routing is based on the **Bearer token** in the request, not the hostname. Your custom hostname is a vanity CNAME plus a Cloudflare-managed TLS certificate — requests to `mcp.yourcompany.com` are transparently forwarded to `connecthub.knotie-ai.pro`.

This means:
- **No integration gateway changes required** — tokens, rate limits, credit charges, and scope enforcement work exactly as before
- **Existing `mcp.knotie-ai.pro` tokens continue to work** — switching to a custom domain does not invalidate existing tokens
- **Partner-minted MCP tokens** remain unaffected; only the server URL displayed to customers changes

## Set up your custom MCP domain

### Step 1 — Enter your domain

1. In the Partner Portal, go to **AI Agents → MCP Tokens**.
2. Find the **Custom MCP Domain** card.
3. Enter the hostname you want to use (e.g. `mcp.yourcompany.com`).
4. Click **Save**.

The platform registers your hostname with Cloudflare and begins issuing an SSL certificate. The status changes to **Pending**.

### Step 2 — Add the CNAME record

While status is Pending, the card shows the DNS record you need:

| Type | Name | Value |
|------|------|-------|
| CNAME | `mcp` (or your chosen prefix) | `mcp.knotie-ai.pro` |

Add this record at your DNS provider (Cloudflare, GoDaddy, Namecheap, etc.). DNS propagation typically takes a few minutes but can take up to 48 hours.

<Tip>
If your DNS is managed by Cloudflare, set the CNAME to **DNS-only** (grey cloud) during verification to avoid proxy interference.
</Tip>

{/* > ℹ️ The **CNAME record details** panel inside the Custom MCP Domain card shows the host + value to add at the DNS provider, plus a verification status badge (Pending / Verified / Failed). Same deferred reason — capture from an account with MCP Whitelabel enabled. */}

### Step 3 — Verify the domain

Once the CNAME record propagates, click **Verify Domain** in the card. The platform:

1. Confirms that the CNAME resolves to `mcp.knotie-ai.pro`.
2. Activates routing so traffic for your hostname is forwarded to the integration gateway.
3. Changes the status to **Verified / Active**.

After verification, the MCP Token snippet shown in the portal updates to use your custom domain.

## Using your custom MCP domain

After verification, use your branded hostname anywhere you previously used `mcp.knotie-ai.pro`. Your MCP Token snippet in the portal already shows the updated URL.

Example config for Cursor, Windsurf, or Claude Desktop:

```json
{
  "mcpServers": {
    "knotie": {
      "url": "https://mcp.yourcompany.com/sse",
      "headers": {
        "Authorization": "Bearer <your-mcp-token>"
      }
    }
  }
}
```

Authentication is still Bearer-token-based. The hostname change does not affect how tokens are issued, validated, or scoped.

## Removing a custom MCP domain

1. Go to **AI Agents → MCP Tokens → Custom MCP Domain**.
2. Click **Remove** (or **Delete Domain**).
3. The platform removes the Cloudflare routing entry and revokes the certificate.
4. All traffic reverts to `mcp.knotie-ai.pro` automatically.

<Warning>
Removing a custom MCP domain immediately breaks any client configurations pointing to that hostname. Inform customers before removing.
</Warning>

## Troubleshooting

| Symptom | What to check |
|---------|---------------|
| Status stuck on **Pending** | Confirm the CNAME was added to the correct DNS zone and the value is exactly `mcp.knotie-ai.pro`. Wait up to 48 hours for propagation. |
| **Verify Domain** fails | Double-check the CNAME value has no trailing path or extra characters. |
| Custom domain option not visible | The `MCP_WHITELABEL_ENABLED` flag may not be active. Contact Knotie support. |
| SSL error immediately after verification | Cloudflare can take up to 15 minutes to finish issuing the certificate. Wait and retry. |
| 401 / token errors on custom domain | Confirm you are using a valid MCP Bearer token. The custom domain does not change authentication requirements. |
